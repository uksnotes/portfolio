# 핵심 동작 흐름

## 공통 흐름

사용자 클릭 → `lib/client-session.ts`가 API 요청 → `app/api/[action]/route.ts`가 로그인과 요청 종류 확인 → `lib/`에서 처리 → Supabase Postgres에 계정별 저장 → 화면 갱신 (변경 요청은 `user_logs`에도 기록)

## 가입·로그인

가입 → `lib/accounts.ts`가 IP별 가입 제한 확인 후 Supabase Auth 계정 생성 + `office_users` 등록 → 바로 로그인 → 매 요청마다 세션과 차단 여부 확인. 관리자가 `/admin`에서 차단하면 세션이 즉시 끊김

## 여행 일정

1. 목적지·날짜·관광지를 입력합니다
2. `research-jobs.ts`가 선택한 AI로 검색을 요청하고 결과를 저장합니다
3. `travel-itinerary.ts`가 출처를 검사하고 식당·명소 순서와 이동을 계산합니다
4. 일정표는 실제 방문 장소만, 맛집 리스트는 전체 식당 후보와 메뉴를 보여줍니다
5. 맛집 변경은 저장된 후보로 다시 계산합니다. AI를 다시 호출하지 않습니다

거리와 시간은 좌표를 이용한 추정입니다. 위치가 없으면 확인 필요로 표시합니다.

## 항공권

검색 조건 → `kiwi-fares.ts` 또는 `flight-fares.ts` → 왕복·직항·날짜·인원·항공사 검사 → `flight-search.ts`가 편도 조합과 가격순 비교 → 결과 표시

Skyscanner는 자동 수집이 아니라 같은 조건의 외부 검색 링크입니다.

## AI 키

키 저장 → 계정별 암호화 → `ai-keys.ts`에서 해당 계정의 키 확인 → 선택한 서비스 호출. 등록한 개인 키가 있으면 미등록 서비스의 서버 기본 키는 사용하지 않습니다. 오류 시 다른 서비스로 자동 전환하지 않습니다.
