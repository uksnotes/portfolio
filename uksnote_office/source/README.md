# HI OFFICE

Private 3D personal workspace with an additional app login, durable D1 tasks/holdings/watchlists, on-demand public Naver HTML quotes and economic news, and transparent weighted technical analysis.

## Runtime configuration
OFFICE_PASSWORD_SALT and OFFICE_PASSWORD_HASH contain the PBKDF2-SHA256 login verifier (100,000 iterations). OFFICE_ENCRYPTION_KEY is a base64 256-bit AES-GCM key. Values are configured as Sites secrets. Never commit .env. Keep the encryption key stable to preserve access to saved provider credentials.

Private platform authentication precedes the app login. Every API operation checks the platform user and an expiring server session. An HttpOnly cookie is retained for compatibility; the client also sends a tab-scoped Authorization bearer token because embedded browsers or dispatch can omit the app cookie. The token is issued only after password verification, checked against the same platform owner, expires after 24 hours, and is revoked on logout. sessionStorage preserves it on same-tab reload; memory handles denied browser storage. It is never put in a URL or localStorage. Records are scoped to the platform user. The dispatcher may supply only authenticated email; identity_aliases maps hashed email/id aliases to a stable internal owner. Missing both trusted identity headers still rejects the request. Passwords and provider keys are never delivered to the client. This initial release has one app username; no public registration.

## Persistence
D1 migrations are schema-only. Record edits use optimistic versions. No runtime seed/reset operation exists. API failures retain previously stored quotes and news. All explicit delete actions require confirmation in the UI.

## Market data
No external API endpoint or key is used. Server-side fetch reads the public Naver mobile stock total page and its embedded __NEXT_DATA__, and the public Naver economy, society, IT, world and ranking page HTML. Article HTML supplies publication dates where available. Fetches are user-triggered, bounded and cached durably. HTTP/parse failures preserve the previous cache and expose an error. These are page snapshots, not streaming or guaranteed real-time prices; market timestamp and retrieval timestamp are distinct.

The short-term model uses only the five completed daily records exposed on the public page. No PER/PBR, peer valuation or long-term moving average is scored. The one-year and five-year charts use numeric OHLCV rows parsed from the public Naver desktop daily-price HTML table. TradingView Lightweight Charts provides wheel/pinch zoom, horizontal dragging, draggable price-scale zoom, crosshairs, candle/close-line switching, volume and keyboard/button controls. No image chart, external API endpoint, key or required CSV is used. Requests fetch at most eight pages in groups of four, with manual redirect mode and explicit HTTP-status checks. Progress is persisted separately, can resume after interruption, and is excluded from normal state payloads. Completed per-stock/per-period history remains available during refresh failures and survives logout/reload; initial requests reuse completed cache for 12 hours. Explicit refresh recollects current data. Source timestamps, actual date coverage, incomplete collection and listing-limited coverage are shown; raw daily prices may not be split-adjusted and the current daily candle changes during market hours. TradingView attribution is retained. Existing CSV uploads remain a separate optional archive. Short-term numeric scoring remains based solely on the five completed daily bars from the public stock page. Each category stores up to ten headlines and article summaries independently. The existing article HTML fetch now extracts only the article body, removes photo captions/ads/scripts, and ranks complete sentences by title relevance, lead position, repeated terms and numeric/event cues. It displays up to two original sentences (360 characters total) and three keywords, with explicit extractive-summary labeling; no external AI or API key is used. Decimal values, negation and complete sentences are retained. Missing bodies are labeled; failed article refreshes retain matching previously saved summaries with a cached timestamp, while unknown publication times remain excluded from scoring. Only brief summary sentences and metadata are persisted, not full article bodies. Ranking shows the first ten distinct publishers’ first-ranked stories in source display order, not a global top-ten ranking. News relation uses deduplicated fetched category stories within seven days; unknown publication times are excluded. No separate holding-specific news search or indirect sector analysis is claimed.

## Analysis
Weights: 3/5-day trend 35, three-session return 25, three-session volume comparison 20, five-close swing/drawdown 10, news keywords 10. Scores are unbacktested screening rules, not probabilities. Technical scores use exactly the latest five completed closes; PER changes and older history cannot affect them. At least 80% factor coverage and five closes are required. Failed/stale fetch (>24h), invalid weights or last bar older than seven days suppress aggregate scores. Old six-factor weight settings are interpreted as the new defaults until the user saves the five-factor configuration; holdings and tasks are not reset. All holdings are scored in a comparison table with per-stock detail.

## Current delivery boundary
Email immediately opens a prefilled Gmail, Outlook, or default mail composer. It also supports durable drafts. The user must press Send in their authenticated provider; opening a composer does not confirm delivery. Alert rules can be saved but are clearly inactive: mail transport and server scheduling are not connected in this release. No emails are sent by the app.

## Character
Click the office to focus. WASD/arrow keys move relative to the camera; E or Enter opens a nearby room. Clicking the floor routes around furniture, clicking a station walks there then opens it. Drag rotates the camera and scroll zooms. Touch direction buttons support press-and-hold. Character state is separate from durable business records.

Session transport regression: production logs on 2026-09-13 showed POST /api/session 200 followed immediately by GET /api/state 401 and a forced /login reload. The client now verifies the session before opening the office, and handles expiry without a full-page redirect. The route/client integration test deliberately discards every cookie and exercises login, verification, state, persistence, module reload, logout/relogin, expiry, denied sessionStorage, owner isolation and CSRF.

Public-page redirect compatibility: Cloudflare Workers rejects redirect:error. The shared news/quote fetcher now uses manual redirects, checks response status, follows only HTTPS on the four fixed Naver news/stock hosts, and stops after three redirects under one timeout. A failed refresh preserves the previous category record. Validation includes five current Naver HTML samples, quote parsing, redirect loops/missing Location/foreign hosts, category isolation and failure preservation.

## Sol expert team
Server-only OPENAI_API_KEY enables five separate gpt-5.6-sol Responses stages: chief of staff, researcher, analyst, reviewer, writer. Research may use OpenAI web search; the other stages receive saved office data and previous reports. This AI feature uses the OpenAI API; the existing public-HTML market and news collection remains unchanged. User-provided context and optional holdings/news snapshots are submitted only after an explicit job request. No key is delivered to browsers.

Jobs, intermediate results, source citations, revisions and approve/hold decisions are stored as owner-scoped ai-job records in D1. The model cannot write approvals. A per-owner active-job guard, optimistic versions, request IDs and leases prevent concurrent stage creation. Unknown submission outcomes require explicit retry rather than automatic resubmission. Failed polling resumes the same remote response. Up to three generation attempts and three report revisions are allowed. Approval records the user's report decision; it does not send email or trade.

The office page advances the next stage while open, including in other rooms. Background OpenAI responses can finish after the tab closes; saved job state resumes when the office reopens. This is not a scheduled autonomous daemon. Five clickable 3D staff expose the same persisted stage status and reports.

Regression coverage uses mocked Responses and SQLite to check five separate model calls, citations, owner isolation, CSRF, duplicate creation, decisions, revisions, errors, cancellation and persistence. A real Responses request was accepted but failed with credit_balance_exhausted; live model output validation remains blocked until API credits are available. No automatic credit purchase is implemented.

## Model selection and provider diagnostics
AI Team Office offers explicit per-job OpenAI Sol or Claude Sonnet 5 / Opus 5 / Haiku 4.5 selection. The choice is persisted separately as an owner preference and copied immutably into each job; changing the picker does not change an existing job or revision. No automatic provider fallback occurs. Legacy jobs retain Sol.

Claude uses the Anthropic Messages API with output_config.format JSON schema. Users can save an owner-scoped Claude API key in the UI; it is encrypted with the existing server AES-GCM key and never returned in API results. ANTHROPIC_API_KEY is an optional server fallback. Saving a key is not a validation or paid generation. The API checks authentication, credits and model access on execution. Claude analyzes provided context only, with an explicit no-web-search notice. Messages use a 90-second timeout and 120-second exclusive lease; interrupted requests are not automatically repeated and may require explicit retry. OpenAI keeps its existing background Responses flow.

A GPT test-call button submits a minimal fixed prompt using the deployed server key, reports the check timestamp/model and distinguishes prepaid-credit errors from organization/project spend limits. It does not inspect exact billing balances or use administrative billing credentials. Calls occur only on explicit user action. Links take the user to API billing and limits. Provider routing, encrypted keys, owner isolation, model persistence, failure behavior, no fallback and diagnostics are covered with mocked API regression tests. Claude live generation cannot be tested until the user supplies an Anthropic key.

## User-managed OpenAI key
AI Team Office now includes a masked GPT key input and explicit save action. Authenticated owners can save their own OpenAI key into the existing AES-GCM encrypted secrets record. The UI only receives key source/status, never the stored key. User keys take precedence over OPENAI_API_KEY for response creation, polling, cancellation and the GPT test call; failed personal keys never silently fall back to the server key. Save preserves other provider credentials and does not invoke a paid API. Empty/invalid values are rejected without changing an existing key. Existing jobs from another OpenAI project may need to be stopped and restarted after switching keys because response IDs are project-scoped. No schema or business-record changes are required.
